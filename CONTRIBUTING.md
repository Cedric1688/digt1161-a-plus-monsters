# Contributing

1. Create an issue with a user story, acceptance criteria, owner and due date. Use one or more course labels: `feature`, `bug`, `doc`, `design`, `good-first-issue`, `help-wanted`, `blocked`.
2. Move it to In progress and create a short-lived branch such as `feature/us2-1-daily-challenge`.
3. Make focused changes. Use meaningful commit messages; prefixes such as `feat:`, `fix:` and `docs:` are encouraged.
4. Open a PR linking the issue. Include relevant validation and screenshots for UI changes.
5. Obtain at least one teammate's approval before merge. Do not self-merge. Review requests should be answered within 72 hours.
6. Mark Done only when acceptance criteria pass, documentation is updated, UI changes work at 375 px, and relevant data permissions are tested.

Do not commit credentials, real user data, raw interview notes, recordings, consent records, student numbers, or personal assessment responses. Use fictional application data. Record actual AI assistance in `docs/ai_usage.md`.

Keep brief weekly notes in `docs/meetings/weekX.md`. Record releases and submission links in `docs/submission.md` only after they exist.
